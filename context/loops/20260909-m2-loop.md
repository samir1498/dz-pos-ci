# M2 loop

Same machinery as the M1 loop (`context/loops/20260909-m1-loop.md`): up to
four agents, the session manages, implementation agents in
`.claude/worktrees/<task>` on `m2/<task>` branches, red first, `just gates`
before every push and a push after every commit, e2e with a port pair per
task, reviewers read-only with the dz-review lenses, the session rebases
(or merges the milestone into a long branch when the rebase conflicts at
every commit), reruns gates, sends findings back to the same agent, merges
`--no-ff` with the `ctx:` trailer, and writes the ledger. Since 2026-09-09
18:21 the session also opens and merges the checkpoint PRs itself.

## Milestone branch

`m2/2026-09-09`, cut from the M1 head after the code sweep merged. Every
task branch starts from it and merges back into it; the checkpoint PR goes
from it to `main`.

## Models

opus for the migration, the money and ledger services, the templates and
every proof review; sonnet for screens, i18n, docs and the boss page;
haiku only for counting.

## Ticks and stop conditions

As in M1: event ticks and a ten-minute heartbeat; never merge red; one
session owns the loop; two cargo builds at most on the box; a finding
that changes a fiscal rule stops the wave and writes the question for the
comptable in `docs/features.md`.

## Lessons (2026-09-09, M2)

- A cargo target dir moved with its worktree (`git worktree move`) keeps
  tauri-build's absolute `OUT_DIR` from the old path and clippy fails on
  it; `cargo clean -p tauri -p dzpos-desktop -p tauri-build` (about 1 GB)
  fixes it. Copying a target dir between worktrees is worse: every
  `CARGO_MANIFEST_DIR` points at the old one.
- `gh pr checks` prints tab-separated columns and the check name holds a
  space (`rust (ubuntu-latest)`); a watcher that splits on whitespace reads
  the platform as the status and never sees green. Split on tabs
  (`awk -F'\t'`) or use `gh pr checks --json name,state`.
- A task can start one wave early when its branch is cut from the head it
  needs (the payments task started from the customers merge while the
  credit sale was still building): tests build the missing rows by hand,
  the e2e is written but run by the session after the rebase.

## For the closing sweep (T8), gathered from the review rounds

- A table-level CHECK tying `debt_ledger.payment_mode` to `kind = 'payment'`
  (the column's CHECK admits null or cash/card on any row; only `append`
  keeps it null elsewhere). Its own migration.
- The route-file export warning shared by till, settings and customers:
  decide once (a lint allow with a reason, or split the route object).
- The ticket suite never reads the rates back from the goldens (the facture
  suite does); align.
- `unpaid_of_customer` must filter `status = issued` before the cancel path
  exists (asked of the payments round; verify it landed).

## Open before the goldens freeze

Open decision 4 (a real printed facture from an Algerian shop), R6 (native
review of the Arabic words file), R8 (the comptable: stamped receipt on a
later cash settlement, yearly series reset). None blocks writing the
code; the Arabic goldens are disclosed as unreviewed like M1's.

Raised by the review rounds, for the comptable: a zero-net facture (a
0 DA line, or a global discount equal to the total) takes a number today;
whether it may be issued at all is a fiscal call. A customer's fiche has
no id route, so a refusal at the till links to the customers list, not the
fiche (sweep).
