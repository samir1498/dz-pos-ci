{#- The half sheet facture: the same page as facture_a4.html, laid out for A5 rather than shrunk onto it. Standalone like its siblings, no external stylesheet and no image, so the bytes this renders are the bytes a browser prints and the bytes a server hands over (features.md §4). A5 is 148 mm wide against A4's 210. Handing the A4 page to a print dialog set to A5 gets a page at 70%, margins included, which is why that is not what this is: the type sizes, the column widths and the totals table here are measured for 134 mm of content, and the layout pins its own paper (`FactureLayout::fixed_paper`) so no caller can ask for it on A4. It holds no rule and no data of its own: every value comes from the same FactureView the standard layout is given, reached through `facture`. A field added for one page is on the other without being listed twice, and a shop comparing the two factures it can print sees the same facts on a smaller sheet, never different facts. What is smaller: the type, the line height, the margins, the heading, and the padding in every box. What is not smaller, and must never be: the mentions décret 05-468 art. 3 requires. A layout that won a line by dropping the NIF would not be a facture, it would be a delivery note with the wrong title. No length in this stylesheet is written as a percentage. An IFU document must not name the tax in any form (CTCA 2026 art. 64), and `names_no_tax` proves the absence by reading the printed page for "%". It reads the body and not the rules above it, deliberately: a width written as a percentage is a length and names no tax. Keeping percentages out of here anyway means the two can never be confused by the next reader. -#} {{ facture.title }} {{ facture.number }} {%- if facture.arabic_unreviewed %} {%- endif %}
